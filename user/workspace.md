# Workspace

The Workspace is where you manage your submissions — both drafts in progress and items you have already submitted or published.

Navigate via **Workspace** in the top nav bar. Two sub-views are available:

- **My Submissions** (`#/workspace/mine`) — your own items
- **Submissions by Others** (`#/workspace/others`) — items you have oversight of

### Status Badges

| Badge | Colour | Meaning |
|---|---|---|
| Workspace | Amber | Draft — only you (and admins) can see it. Not yet in DSpace's public index. |
| Archived | Green | Published in the repository. Visible to all (subject to access policies). |
| Withdrawn | Red | Previously published, now withdrawn from public view. Still visible to administrators. |

### Columns Explained

| Column | What it shows |
|---|---|
| Title / ID | Item title (linked). Below: workspace ID (`ws/42`) for drafts, or UUID prefix for published items. |
| Status | Current lifecycle state — Workspace, Archived, or Withdrawn. |
| Type | The `dc.type` metadata value set in the form. |
| Form | The submission form / process used (e.g. `publication`, `product`). |
| Valid | Green **OK** = no validation errors. Red **N errors** = required fields missing. Hover the badge for details. |
| Modified | Last modification timestamp. |
| Actions | **View →** opens the item detail. **Clone** (workspace items only) duplicates the metadata into a new draft. |

### Searching Your Submissions

The search box above the table filters by title in real time. Type a few characters and the list updates immediately. Pagination controls appear at the bottom when you have more than one page of results (20 items per page).

## Validation Errors

If an item has a red **N errors** badge, click **View →** to open the detail page. The error details are shown there — they typically indicate required fields that DSpace expects before the item can be submitted.

<div class="callout callout-warn">
<span class="callout-title">Items with errors cannot be submitted</span>
DSpace will reject submission of a workspace item that has validation errors. Fix all flagged fields before clicking Submit.
</div>

Common validation errors:

| Error | Fix |
|---|---|
| `dc.title is required` | Add the item title in the submission form |
| `dc.date.issued is required` | Add a publication or issue date |
| `dc.contributor.author is required` | Add at least one author |
| `dc.type is required` | Select a type from the dropdown |

## Cloning a Workspace Item

The **Clone** button appears on workspace items (status = Workspace, not yet archived). Cloning creates a new draft pre-filled with the same metadata — useful for creating several similar records without re-entering all fields.

<ol class="steps">
<li><div>Find the item in My Submissions and click <strong>Clone</strong>.</div></li>
<li><div>The Cockpit fetches the source item's metadata and creates a new workspace item in the same collection.</div></li>
<li><div>The new draft opens in My Submissions with the title and all metadata copied. Edit as needed.</div></li>
</ol>

<div class="callout callout-info">
<span class="callout-title">Files are not cloned</span>
Bitstream files (PDFs, datasets, etc.) attached to the original item are <strong>not</strong> copied to the clone. You will need to re-upload any files to the new draft.
</div>

## Submissions by Others

Navigate to **Workspace → Submissions by Others** to see items submitted by colleagues that you have oversight of.

<div class="callout callout-info">
<span class="callout-title">Who sees this view?</span>
Items appear here if you have review or administrator permissions on the collection they are submitted to. Typical roles: collection reviewer, collection admin, DSpace administrator. Regular users with no review role will see an empty list.
</div>

The table shows the same columns as My Submissions plus the submitter's name. You can view any item's detail page, but editing is restricted to the original submitter and administrators.

---

## Viewing an Item (Detail Page)

Click **View →** on any item — in My Submissions, Submissions by Others, search results, or the communities browser — to open the item detail page.

### What the detail page shows

| Section | Contents |
|---|---|
| Title & Status | Item title, entity type label, current lifecycle status badge |
| Metadata | All metadata fields, grouped by schema (dc.*, crisrp.*, etc.) |
| Files (Bitstreams) | Attached files — downloadable, and (if you have permission) uploadable / deletable |
| Raw JSON | Expandable panel showing the raw DSpace REST API response. Useful for debugging. |

### Uploading a File

<ol class="steps">
<li><div><strong>Open the item detail page</strong><br>Click <strong>View →</strong> on a workspace item.</div></li>
<li><div><strong>Scroll to the Files section</strong><br>If you have edit permission, an upload area appears below the existing files list.</div></li>
<li><div><strong>Drag and drop or click to browse</strong><br>Select the file from your computer. The upload starts automatically and a progress indicator appears.</div></li>
<li><div><strong>The file appears in the list</strong><br>Once uploaded, the file (bitstream) is visible in the Files section and is attached to the item in DSpace.</div></li>
</ol>

### Deleting a File

Click the **Delete** button next to a file in the bitstream list. A confirmation prompt appears. Deletion is permanent — the file is removed from DSpace and cannot be recovered via the Cockpit.

<div class="callout callout-danger">
<span class="callout-title">File deletion is permanent</span>
Once deleted, a file cannot be recovered through the Cockpit. If you delete a file accidentally, contact your repository administrator immediately — they may be able to restore it from a backup.
</div>

### Navigating Back

Click the **← Back** button at the top of the detail page, or use the browser's back button, to return to the list you came from.
